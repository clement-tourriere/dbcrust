# S3 / R2 / MinIO connector (`s3` feature)

Wave 3.3. Read [aws-common.md](aws-common.md) first (versions, ring-only configuration, credentials, broker caveats). This file only records what is S3-specific.

## 1. Library choice

| Candidate | Result | Verdict |
|---|---|---|
| **`aws-sdk-s3` `=1.152.0`** (2026-10-01, 14 d; Apache-2.0; `aws-sdk-rust-ci`) + `aws-config =1.12.0` + `aws-smithy-http-client rustls-ring` | ring only (no aws-lc-*), audit clean beyond the shared rustls baseline, tokio, hyper 1.x/rustls 0.23 (locked) | **Recommended** |
| `object_store =0.13.2` `aws` (the version DataFusion 53.1 uses; already locked *without* the `aws` feature) | no aws-lc (uses `ring`, `reqwest 0.12` rustls) but pulls **`quick-xml 0.39.4`: RUSTSEC-2026-0194 and RUSTSEC-2026-0195** (fixed >= 0.41.0). Probe measured: 1 new pair (`quick-xml 0.39.4`), 20 s wall / 94 s CPU, 2.56 MB | Rejected until upstream bumps quick-xml (the policy forbids new advisory suppressions) |
| `object_store =0.14.2` `aws` (2026-09-15) | quick-xml 0.41 (fixed) but the `aws`/`azure`/`gcp` features enable `reqwest/rustls` + hard `aws-lc-rs` | Rejected (aws-lc), and it is not the version DataFusion 53 links |
| MinIO/R2/Ceph | all S3-compatible through the SDK with `endpoint_url` + `force_path_style(true)` (MinIO) / region `auto` (R2) | covered by the SDK |

Measured (probes, DBCrust release profile): `aws-config` base **29** new pairs; `+aws-sdk-s3` **34** (the S3 SDK itself adds 5: `aws-sdk-s3`, `aws-smithy-checksums`, `aws-smithy-eventstream`, `crc-fast`, plus a `tokio-util` bump); clean build 46 s wall / 159 s CPU; stripped binary 4.11 MB (**+3.74 MB** over the tokio-only baseline, most of it the shared AWS base: aws-config alone is 3.81 MB).

**DataFusion over S3 without `object_store`'s `aws` feature**: DataFusion 53 queries any `object_store::ObjectStore`. The core `object_store 0.13.2` crate is already locked (no `aws`, no quick-xml). Implement a ~300-line `ObjectStore` adapter on top of `aws-sdk-s3` (`get_opts` with ranges, `list`/`list_with_delimiter`, `head`) and register it with the existing `DataFusionClient` for `s3://bucket/prefix/*.parquet|csv|json`. This reuses the files engine, uses ring via the SDK client, and avoids both advisories. (Mark as phase 2; phase 1 is browse/get.) **S3 Select is not an option**: AWS closed it to new customers.

## 2. URL and `ConnectionInfo` mapping

- Schemes: `s3://bucket[/prefix]`, `r2://<account-id>/bucket[/prefix]` (endpoint `https://<account>.r2.cloudflarestorage.com`, region `auto`), `minio://host:9000/bucket[/prefix]?tls=false` (alias for `s3` with `endpoint` + `path_style=true`), `gs://` out of scope.
- `s3://my-bucket/logs/2026/?region=eu-west-1&profile=prod-ro&endpoint=https://s3.example.com&path_style=true&anonymous=false`
- `ConnectionInfo`: `host` = endpoint host or None (AWS), `port`, `username` = `access_key_id` (or None when ambient), `password` = `secret_access_key`, `database` = **bucket**, `file_path` = key prefix (kept out of `options` so prefix navigation works like a directory), `use_tls`, `options`: `region`, `profile`, `role_arn`, `path_style`, `endpoint`, `session_token` (secret), `anonymous`.
- `DatabaseTypeExt`: `default_port = None`, ssh tunnel false (SDK endpoint), `is_file_based = false`, `requires_authentication = false` (ambient credentials, anonymous public buckets), `supports_json_explain = false`.
- **Secrets**: `secret_access_key`, `session_token`; `access_key_id` is an identifier bound in `TargetBinding.user`. Pre-signed URLs are bearer secrets and must never be produced for agents.
- `TargetBinding`: engine=`s3`, host=endpoint or region, port, database=bucket, user=access key id / profile / role arn, tls_mode.

## 3. Query model

Object stores have no SQL. Typed operations, exposed both as commands in the REPL and as the agent's `list_tables`/`describe_table`/`query`:

| Command / op | S3 call | Result rows |
|---|---|---|
| `ls [prefix]` / `\dt` | `ListBuckets` (account level) or `ListObjectsV2(prefix, delimiter="/")` paginated | columns `key, type (dir/object), size, last_modified, storage_class, etag` |
| `stat key` / `\d key` | `HeadObject` (+ `GetObjectAttributes`) | one row of attributes (content-type, SSE, metadata, version id) |
| `cat key [--bytes N]` | `GetObject` with `Range: bytes=0-N-1` | single `line`/`bytes` column; text only, binary shown as size + hex head |
| `SELECT ... FROM 's3://bucket/prefix/*.parquet'` (phase 2) | DataFusion + SDK-backed `ObjectStore` | normal tabular rows; schema from Parquet footers / CSV sniffing |
| `\l` | `ListBuckets` | bucket, creation date |

Metadata provider mapping: `get_schemas` -> buckets; `get_tables(bucket)` -> top-level prefixes (delimiter listing, capped); `get_columns(prefix_or_file)` -> object attributes columns or, for Parquet/CSV objects, the inferred schema (reads the footer by range); completion = bucket names and prefix segments from the last listing (cached with TTL). Rows are always strings; NULL for missing storage class/etag.

## 4. Safety / broker capabilities

| Capability | Status |
|---|---|
| Read-only | **Not provable client-side** (IAM). `ReadOnlyKind::ClientStructural`: the connector exposes `ls`/`stat`/`cat`/SQL-over-files only - there is no code path to `PutObject`, `DeleteObject`, `CopyObject`, multipart, ACL/policy/lifecycle, `PutObjectTagging`, or `CreatePresignedRequest`. `native_read_only = false` unless the enrollment probe `iam:SimulatePrincipalPolicy` (if permitted) shows no `s3:Put*/Delete*` for the bucket. Owner recipe: IAM policy with `s3:ListBucket`, `s3:GetObject`, `s3:GetBucketLocation` on the one bucket/prefix (with `s3:prefix` condition) and an explicit `Deny s3:Put*`, `s3:Delete*` |
| Statement timeout | SDK `TimeoutConfig` (operation/attempt/connect/read) - native |
| Cancellation | drop the future = abort the HTTP request (native); GET body streams stop immediately |
| Row/byte limits | native for bytes (`Range` header, `max_bytes` per object, `max_keys` <= 1000 per page, `max_pages`); rows for file SQL via DataFusion `LIMIT` + fetch-side truncation |
| Denied | everything mutating; presigning; `GetObject` without `Range` above `max_bytes`; cross-account `bucket` override; SSE-C; requester-pays buckets unless explicitly enabled; access to objects larger than `max_object_bytes` for SQL scans (stat first) |

Egress/request costs are real: every `cat`/scan reports bytes read and request count as a notice; the broker audit log records `bytes` (G.4 audit field).

DML opt-in (D2): **not offered**; objects are written by other tooling. Phase 3 could add owner-enabled `put` into a single sandbox prefix; out of scope.

## 5. Testing strategy

- Inline unit tests: URL parsing (virtual-hosted vs path style, `r2://`, `minio://`, IPv6 endpoints, redaction canaries for `secret_access_key`/`session_token`), delimiter-listing -> tree/rows mapping (pagination boundaries, empty prefix, keys containing `/` runs and unicode), range clamp arithmetic, text/binary sniffing, ObjectStore adapter `get_opts` range translation. SDK calls tested with `aws-smithy-http-client` `test-util` `StaticReplayClient` (dev-dependency only).
- Opt-in integration (`S3_TEST_ENDPOINT`/`AWS_ENDPOINT_URL`, skipped when unset): `docker run -p 9000:9000 minio/minio server /data` (seed with `mc`), and `localstack/localstack` (S3 is in the free tier). R2 smoke only by hand.

## 6. Effort, risks, feature gating

- **Effort: M** for phase 1 (browse/stat/cat, metadata, completion, GUI form, ~5 days on top of the shared AWS base); **+M** for the DataFusion `ObjectStore` adapter (phase 2). Rich CRUD (multipart, presign) stays P3.
- Cargo feature `s3` (implies `aws`). **Opt-in** (D3).
- Risks: (1) the `object_store` `aws` feature is blocked by RUSTSEC-2026-0194/0195 (0.13) or aws-lc (0.14) - re-check when DataFusion moves to object_store 0.14 *and* upstream drops the hard aws-lc dependency, then the adapter could be replaced; (2) DataFusion version coupling to the `object_store` crate version in the lock; (3) listing very large prefixes is slow and billed (1000 keys/request) - cap pages; (4) IAM-based read-only cannot be verified; (5) region redirects / bucket region discovery (`GetBucketLocation` denied) - require explicit `region`; (6) MSRV 1.94.1.
