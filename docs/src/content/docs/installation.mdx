## Pre-built binaries (recommended)

<Tabs>
  <TabItem label="macOS / Linux">
    ```bash
    curl -fsSL https://clement-tourriere.github.io/dbcrust/install.sh | sh
    ```

    Customise:

    ```bash
    # Specific version
    DBCRUST_VERSION=v0.25.0 curl -fsSL https://clement-tourriere.github.io/dbcrust/install.sh | sh

    # Custom directory
    DBCRUST_INSTALL_DIR=/usr/local/bin curl -fsSL https://clement-tourriere.github.io/dbcrust/install.sh | sh
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    irm https://clement-tourriere.github.io/dbcrust/install.ps1 | iex
    ```

    Customise:

    ```powershell
    $env:DBCRUST_VERSION = "v0.25.0"; irm https://clement-tourriere.github.io/dbcrust/install.ps1 | iex
    ```
  </TabItem>
</Tabs>

This installs two binaries: `dbcrust` (full name) and `dbc` (short alias).

The macOS binaries are signed with a Developer ID and notarized by Apple, so they run even when downloaded with a browser.

## Homebrew (macOS, Linux)

```bash
brew install clement-tourriere/tap/dbcrust
```

This installs `dbcrust`, `dbc` and `dbcrust-agent` with their shell completions. `brew upgrade dbcrust` (or `dbcrust --update`) keeps it current.

The first time it connects to a database on your local network (or to a Docker container's address), macOS asks whether DBCrust may access the local network: allow it. You can change this later in System Settings → Privacy & Security → Local Network. See [Desktop GUI](/dbcrust/user-guide/gui/).



## From source

### Prerequisites

- **Rust** stable — install from [rustup.rs](https://rustup.rs/)
- **mise 2026.8.16+** (optional but recommended) — manages dev tools and the Rust build cache. Not installed? Use the repository's `./bin/mise` wrapper in its place: it downloads a pinned mise on first use.

```bash
git clone https://github.com/clement-tourriere/dbcrust.git
cd dbcrust

# Option A: with mise (recommended) — or ./bin/mise without installing mise
mise install            # installs Mr Boxington, Commitizen, hk, Bun (docs site), etc.
mise run build          # release build
mise run build:dev      # debug build (faster)
mise run install        # build + install dbcrust and dbc into ~/.cargo/bin

# Option B: cargo only (CLI only)
cargo install --path . --locked --force

# Slim build: PostgreSQL, MySQL and SQLite only (no DataFusion, MongoDB,
# ClickHouse, Elasticsearch, Docker, AI, TUI or clipboard): a much smaller binary
# and a much shorter build
cargo install --path . --locked --force --no-default-features --features standard
mise run install:slim    # the same through mise
```

The default build includes every engine and add-on. See [Build features](/dbcrust/user-guide/development/#build-features) to pick exactly what you need.

With mise, Cargo builds go through [Mr Boxington](https://mr-boxington.jdx.dev/), a shared build cache: rebuilds, other branches and worktrees reuse compiled crates. See [Build cache](/dbcrust/user-guide/development/#build-cache-mr-boxington).

### Building the desktop app

The desktop app is pure Rust ([GPUI Kit](https://gpui-kit.com)), so only a Rust toolchain is required. On Linux, install the GPUI system libraries first, for example on Debian/Ubuntu: `sudo apt install libxkbcommon-x11-dev libwayland-dev libfontconfig-dev libx11-xcb-dev libvulkan1`.

```bash
mise run gui:dev          # run the app (dev build, optimised dependencies)
mise run gui:build        # optimised build → target/gui-release/dbcrust-gui
mise run gui:install      # install dbcrust-gui into ~/.cargo/bin
mise run gui:bundle       # macOS: target/gui-release/bundle/DBCrust.app
mise run macos:package    # macOS: CLI archive + DMG like a release → target/macos-dist/

# no mise installed: the committed wrapper
./bin/mise run gui:dev

# cargo only
cargo run -p dbcrust-gui
cargo install --path gui --bin dbcrust-gui --locked
```

See [Desktop GUI](/dbcrust/user-guide/gui/) for details.

### Python bindings

```bash
mise run py:dev           # maturin develop (editable install)
mise run py:build         # build wheel
# or
pip install -e ./python
```

## Shell completion

Enable tab-completion for URL schemes, container names, session names, compatible data files, and flags.

<Tabs>
  <TabItem label="Bash">
    ```bash
    mkdir -p ~/.local/share/bash-completion/completions
    dbcrust --completions bash > ~/.local/share/bash-completion/completions/dbcrust
    dbc --completions bash > ~/.local/share/bash-completion/completions/dbc
    source ~/.bashrc
    ```
  </TabItem>
  <TabItem label="Zsh">
    ```bash
    mkdir -p ~/.zfunc
    dbcrust --completions zsh > ~/.zfunc/_dbcrust
    dbc --completions zsh > ~/.zfunc/_dbc
    ```

    Add to `~/.zshrc` (before `source $ZSH/oh-my-zsh.sh` if you use oh-my-zsh):

    ```bash
    fpath+=~/.zfunc
    autoload -U compinit && compinit
    ```
  </TabItem>
  <TabItem label="Fish">
    ```bash
    dbcrust --completions fish > ~/.config/fish/completions/dbcrust.fish
    dbc --completions fish > ~/.config/fish/completions/dbc.fish
    ```
  </TabItem>
  <TabItem label="PowerShell">
    ```powershell
    dbcrust --completions powershell > "$HOME\Documents\PowerShell\Completions\dbcrust.ps1"
    ```
  </TabItem>
  <TabItem label="Nushell">
    ```bash
    dbcrust --completions nushell | save -f ($env.NU_VENDOR_AUTOLOAD_DIR | path join "dbcrust.nu")
    ```
  </TabItem>
</Tabs>

Completions are answered live by the `dbcrust` binary itself (the script calls
it back at Tab time), so saved sessions, running Docker containers, and
compatible files are always current — just keep `dbcrust` on your `PATH`.

After setup:

```bash
dbc pos[TAB]            → postgres://
dbc docker://[TAB]      → lists running containers
dbc session://[TAB]     → lists saved sessions
dbc --[TAB]             → shows flags
```

## Supported databases

| Database | Versions | URL scheme |
|----------|----------|------------|
| PostgreSQL | 9.6+ | `postgres://` |
| MySQL | 5.7+ | `mysql://` |
| SQLite | 3.6+ | `sqlite://` |
| ClickHouse | 20.3+ | `clickhouse://` |
| MongoDB | 4.0+ | `mongodb://`, `mongodb+srv://` |
| Elasticsearch | 7.x+ | `elasticsearch://`, `es://` |

File formats (via Apache DataFusion):

| Format | URL scheme |
|--------|------------|
| Parquet | `parquet://` |
| CSV | `csv://` |
| JSON | `json://` |

Bare paths such as `users.csv`, `warehouse.parquet`, and `app.sqlite` are also accepted and inferred from the extension.

Special schemes:

| Scheme | Purpose |
|--------|---------|
| `docker://` | Connect to database containers |
| `session://` | Saved sessions |
| `recent://` | Recent connections |
| `file://` | Interactive compatible-file picker |
| `vault://` | HashiCorp Vault credentials |

## Updating

DBCrust can update itself. It detects how it was installed (uv tool, pipx, pip, cargo, standalone binary), checks GitHub for the latest release, and runs — or prints — the matching upgrade command:

```bash
dbcrust --update
```

Or update manually through your install channel:

```bash
# Pre-built binary — just re-run the installer
curl -fsSL https://clement-tourriere.github.io/dbcrust/install.sh | sh

# uv
uv tool upgrade dbcrust

# pipx
pipx upgrade dbcrust

# pip
pip install --upgrade dbcrust

# From source
git pull && mise run install      # or: cargo install --path . --locked --force
```

## Uninstalling

```bash
# uv
uv tool uninstall dbcrust

# pip
pip uninstall dbcrust

# cargo
cargo uninstall dbcrust

# Remove config (optional)
rm -rf ~/.config/dbcrust
```

## Troubleshooting

:::danger[Command not found]
Make sure the install directory is in your `PATH`:
```bash
export PATH="$HOME/.local/bin:$HOME/.cargo/bin:$PATH"
```
:::

:::danger[SSL errors]
Update your CA certificates, or test with SSL disabled:
```bash
dbcrust postgres://user:pass@localhost/db?sslmode=disable
```
:::

:::danger[Desktop app won't build]
Update Rust (`mise upgrade rust` or `rustup update`; 1.85 or newer). On Linux, install the GPUI system libraries listed in [Building the desktop app](#building-the-desktop-app). The backend alone builds without them: `cargo test -p dbcrust-gui-core`.
:::
